## Overview

In Mobile Edge Computing (MEC), latency-sensitive tasks generated by end-user devices (smartphones, smart cameras, autonomous IoT sensors) must be offloaded to nearby edge servers. However, edge nodes possess heterogeneous processing capacities ($f_j$) and varying network link delays ($T_{net}$). Naive dispatching policies such as **Random** or **Round Robin** frequently overload low-capacity edge servers while leaving high-capacity nodes underutilized.

This project implements an $O(M)$ **Load and Latency-Aware Scheduler** that:
1. Tracks real-time server queue backlogs via periodic telemetry feedback.
2. Evaluates end-to-end completion latency (network delay + queue wait time + active CPU execution).
3. Dynamically routes tasks to prevent bottlenecks and minimize average system response time.

## System Architecture

The simulation models a **closed-loop three-tier architecture**:

```text
+--------------------+      Offload Request      +---------------------------+      Dispatch Task      +-----------------------+
|  1. User Devices   | ------------------------> |    2. Task Scheduler      | ----------------------> |   3. Edge Servers     |
|  (Task Gen: D, C)  |                           | (Load & Latency Aware)    | <---------------------- | (Queue + CPU Core)    |
+--------------------+                           +---------------------------+    Telemetry Feedback   +-----------------------+
          ^                                                                                                        |
          |________________________________________ Round-Trip Result Return ______________________________________|
```

1. **User Devices:** Continuously generate tasks characterized by payload size ($D$) and computational workload ($C$).
2. **Task Scheduler:** Buffers incoming tasks, processes routing decisions, and monitors server queue states via telemetry packets.
3. **Edge Servers:** Drain task queues proportionally to their CPU speeds ($f_j$) and return processed results back to originating devices.

## Quick Start

### 1. Running the Python Benchmark

Ensure you have Python 3.8+ along with `numpy` and `matplotlib` installed:

```bash
pip install numpy matplotlib
python edge_offloading_simulation.py
```

Running the script prints comparative metrics (mean latency, max latency, queue wait standard deviation, and per-server task distribution) to the console and displays a 3-panel comparative chart.

### 2. Launching the Interactive Real-Time Visualizer

No build step or server backend is required. Simply open `edge_server_simulation_v7_en.html` directly in any modern web browser (Chrome, Edge, Firefox, Safari):

* Switch policies on the fly between **Load & Latency-Aware**, **Round Robin**, and **Random**.
* Adjust animation speed from **`0.1x` to `2.0x`** to inspect individual packet lifecycles.
* Monitor the **System Event Log** sidebar for timestamped `[CREATE]`, `[ROUTE]`, `[EXEC]`, and `[DONE]` events.
* Click **`Fullscreen`** for presentation mode.

## Experimental Results

Evaluated across $N = 60$ bursty tasks over three heterogeneous edge nodes (`CPU = 100, 60, 40 MCycles/s` and `T_net = 0.50s, 0.10s, 0.05s`):

| Scheduling Policy | Mean Latency (s) | Load Balance Behavior |
| :--- | :---: | :--- |
| **Random** | ~1.58s | High variance; severe congestion spikes on low-CPU node |
| **Round Robin** | ~1.52s | Unbalanced; overloads weak nodes due to equal task count split |
| **Proposed (Load & Latency-Aware)** | **~0.83s** | **~45% latency reduction; equalized queue wait times across nodes** |
